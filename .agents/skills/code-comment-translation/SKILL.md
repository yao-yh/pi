# 代码解析与注释翻译

在代码解析过程中同步完成英文注释中文化。用户的明确范围和要求始终优先于本技能。

## 范围

- 用户指定文件或目录时，只处理该范围；未指定时，优先处理仓库内的 `src` 目录。
- 除非用户明确要求，不处理 `test`、`tests`、`__tests__`、测试夹具、benchmark、示例、文档、依赖、构建产物和生成文件。
- 如果目标目录同时包含源码和测试文件，默认排除 `*.test.*`、`*.spec.*` 及明显的测试辅助代码。
- 不因翻译注释修改业务逻辑、类型、标识符、字符串、格式或无关文件。

## 解析时翻译

1. 修改前完整读取当前文件，结合代码语义理解注释，避免逐句直译造成含义错误。
2. 解析到英文自然语言注释时，在同一处理批次内翻译为简体中文，不要等全部代码解析结束后再集中翻译。
3. 保留标识符、API 名称、协议名、命令、路径、URL、代码片段、错误码和必要的英文术语；只翻译其说明性文字。
4. 保留注释类型与结构，包括行注释、块注释、JSDoc/TSDoc 标签和 Markdown 格式。可翻译 `@param`、`@returns` 等标签后的说明，不修改标签本身。
5. 不翻译或破坏工具指令与机器可读标记，例如 `eslint-disable`、`@ts-ignore`、覆盖率指令和许可证标识。
6. 混合中英文注释只翻译仍属英文说明的部分。已经准确的中文注释保持不变。
7. 除非用户明确要求，或项目级指令要求为本次修改的关键逻辑补充说明，否则只翻译现有注释，不新增注释。

## 首次全量解析进度

“首次全量解析”指用户要求首次完整解析某个仓库、包或模块，而不是单个文件或一次局部问题定位。

- 进度文件固定为仓库根目录的 `COMMENT_TRANSLATION_PROGRESS.md`。
- 开始全量解析前先读取该文件。文件不存在时创建；文件已存在时保留准确记录，并按当前目标范围新增或续写对应章节，不得重置其他范围的进度。
- 首次写入目标范围时记录：解析目标、默认排除项、开始时间、待处理批次或目录、当前状态和验证边界。
- 每完成一个可恢复批次就更新：已完成文件或目录、当前文件、下一批次、发现的例外和更新时间。
- 发生中断、错误或范围变化时，先记录停止位置、原因和可恢复入口，再结束当前处理。
- 只有纳入范围的源码均已检查、英文说明性注释均已处理后，才能标记该范围完成。测试等默认排除项不计入完成条件。
- 后续局部解析无需更新进度文件；后续针对同一范围的全量解析应先按已有记录恢复，避免重复处理。

建议使用以下最小结构；已有文件可沿用其更详细的结构：

```markdown
# 注释中文化进度

## <目标范围>

- 状态：进行中 | 已完成 | 已中断
- 范围：<源码目录或文件>
- 排除：<默认排除项及用户指定排除项>
- 已完成：<批次、目录或文件>
- 当前：<正在处理或停止的位置>
- 下一步：<可恢复动作>
- 更新时间：<带时区的时间>
- 验证：<实际执行的检查及未执行项>
```

## 检查与交付

- 使用 `rg --files` 或等效方式枚举目标源码，明确应用排除规则。
- 分批处理较大范围，确保每个文件在修改前均已完整读取，并及时保存进度。
- 完成后检查差异，确认源码改动仅涉及目标注释和必要的进度记录；按项目要求执行适用检查。
- 简要说明解析范围、已翻译内容、排除项、进度文件状态，以及未执行的验证。
